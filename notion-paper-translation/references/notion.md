# Notion 写入与验收

使用已连接的 Notion 工具。写入前用 fetch 读取 `notion://docs/notion-flavored-markdown-spec`，以其当前语法为准。普通页面用 page ID 创建子页；若用户指定的是数据库，读取数据源 schema，按实际标题属性新增条目。页首注明原文链接、版本和范围。

## 数学与表格

独立公式用两个各占一行的 `$$` 界定，前后留空行。行内公式用 `$…$`。块 API 可直接写入 `equation`。优先取 TeX 原式或结构化 HTML 的数学源（例如 arXiv HTML 的 MathML alttext），对照 PDF 检查上下标、粗体、对齐和符号。将自定义命令展开成受支持的 KaTeX 表达式；用相邻的短文字保留公式编号和引用，特别是多行共用编号时。复杂表格用当前规范支持的原生表格写法，保留表头与数据对应。若单元格需引用独立公式，使用式号并在附近放置相应公式块。

## 图片

- 同版本 HTML 有原图时，以文档 URL 为基准解析相对路径，核对图片 URL 的状态与媒体类型。用 Notion 的 create_attachment 从公开直链导入，再使用返回的 markdown_source 或 suggested_markdown。遇到限流时遵循返回的等待时间，串行续传尚未上传的图片。
- 本地文件或 PDF 裁图使用 Notion 的 create_file_upload。按工具返回的地址和请求头发送一次 multipart/form-data POST，文件字段为 file。使用上传成功响应中的 Markdown 引用。多面板图核对每个面板，尽可能在原组图注旁保留原顺序。逐个插为独立 image 块。
- 如果附件导入不可用且原图直链可读，可使用验证过的直链作为图片块 source。图注保留图号及子图标识。写入后用稳定的 notion-file-block 引用确认附件可解析，短期下载签名只用于核验。失败时记录具体图号并修复有问题的图片块。

## 分批写入及复核

以完整段落或小节为分批边界。用 update_page 的 insert_content 命令向页尾续写时，将本批 Markdown 放入 content 字段。创建响应不明确时，先在目标下检查标题、版本和已写入的内容；续写时先读页，避免因超时重复建页或插入。只改本次译文的对应部分。逐节回读，核对原文结构、独立公式块及编号、行内公式、图号和面板、表格及引文。检查反序列化后没有出现文字形式的 LaTeX、未知块或图片占位。父页可用子页列表复核。用户需要新页时保留其他页面。
